# Session 6 — 2026-09-25

## What was changed
Built the entire remaining product surface in one session, per explicit
instruction to "do all of the queue now, including reports and summaries."
This was the whole session-5 queue: JWT_SECRET setup (local placeholder
only — see below), admin seed script, dashboard, take-attendance, students,
batches, leaves, calendar, and reports (with CSV export).

### Schema
- Added two DB-enforced constraints via a new migration
  (0001_flimsy_blackheart.sql): a partial unique index so at most one batch
  can ever have `is_current = true`, and an index on
  `attendance_records.date` for calendar/report range queries, plus an
  index on `leaves.student_id`.

### Shared logic layer (new)
- `src/lib/date.ts` — all date math, "today" computed in Asia/Kathmandu.
- `src/lib/result.ts` — `Result<T>` type used by every service function.
- `src/lib/api.ts` — `authorize`, `parseBody/parseQuery/parseParams`,
  `handleError` (maps PG 23505/23503 to 409, else generic 500), `respond`.
- `src/lib/validation/*` — one Zod file per resource.
- `src/lib/db/queries/*` — one file per table (users, batches, students,
  attendance, leaves). No route handler queries `db` directly anymore.
- `src/lib/attendance/summary.ts` — the ONE place attendance totals are
  computed (absenceCount/lateCount/leaveDays/absentDays, daily present/
  absent/late/leave counts). Attendance record wins over an overlapping
  leave range for the same date — documented in the file header.
- `src/lib/attendance/service.ts` — dashboard, calendar month, day list,
  mark/clear attendance, lookup-by-roll.
- `src/lib/attendance/csv.ts` — report export, formula-injection-safe.
- `src/lib/roster/service.ts` — batch/student/leave mutations (uniqueness
  checks, atomic current-batch switching, cascading student delete).
- `src/lib/auth/page-guards.ts` — `requirePageSession()`/`requireAdminPage()`
  for Server Component pages (mirrors `authorize()` for API routes).
- Session payload gained a `name` field (was `{userId,username,role}`, now
  `{userId,username,name,role}`) so the nav can show a real name without an
  extra query per page load. Updated jwt.ts, session creation in the login
  route, and /api/auth/me accordingly.
- Login route refactored to use the shared query layer and a real
  `DUMMY_PASSWORD_HASH` bcrypt compare on unknown usernames (was already
  timing-safe-ish before, now goes through the shared `getUserByUsername`).

### API routes (new)
/api/students, /api/students/[id], /api/batches, /api/batches/[id],
/api/leaves, /api/leaves/[id], /api/attendance, /api/attendance/lookup,
/api/calendar, /api/dashboard, /api/reports/summary, /api/reports/export,
/api/admin/users, /api/admin/users/[id]/password.

### Pages (new) — all under a new `src/app/(app)/` route group
Moved the old `src/app/page.tsx` into the group. New `(app)/layout.tsx`
calls `requirePageSession()` and wraps everything in `<NavShell>`
(`src/components/nav-shell.tsx`) — role-aware nav, logout button.
- `/` — dashboard (today's counts, batch totals, top-5 absentees). **Both
  admin and staff land here** — this was an explicit product decision:
  admin can also take attendance, so there's no separate admin landing.
- `/attendance` — the core workflow: date picker, roll-number input,
  Absent/Late/Leave buttons, "mark present" undoes a record (with confirm).
- `/students`, `/batches`, `/admin/users` — admin-only (server-side
  `requireAdminPage()` + every mutating route double-checks
  `authorize(["admin"])`).
- `/leaves`, `/calendar`, `/reports` — both roles.
- Design: crimson `#9E1B32` accent, light/dark via Tailwind's
  `dark:` classes (globals.css already had prefers-color-scheme vars).

### Infra
- Renamed `src/middleware.ts` → `src/proxy.ts` (Next.js 16 deprecated the
  old convention; function renamed `middleware` → `proxy`, same behavior,
  same matcher). `next build` no longer prints the deprecation warning.
- Added `scripts/seed-admin.ts` (interactive or `--flag=value`, idempotent —
  re-running with an existing username resets password + sets role=admin).
  Added `tsx` as a dev dependency to run it (`npm run seed:admin`).
- Added `npm run db:generate` / `db:migrate` convenience scripts.
- Fixed the stale `.clauderules`: removed all references to `MEMORY.md` and
  the old `memory-YYYY-MM-DD-HHMMSS.md` naming, removed the "empty route
  group" folder-tree entries that never existed in git, updated every
  "middleware" reference to "proxy", rewrote the folder tree to match what's
  actually in the repo now.
- Rewrote `.claude/docs/architecture.md` in full to reflect the built state
  (previous version described only auth + schema as built; product surface
  was entirely TODO). Added session-6 notes to context.md and gotchas.md
  (Zod v4 `flattenError`, Next 16 proxy rename, `db.batch` vs
  `db.transaction` on neon-http, AGENTS.md auto-regeneration, font-fetch
  network requirement).
