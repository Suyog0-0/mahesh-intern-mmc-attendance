## Durable facts / conventions to remember
- Path alias `@/*` → `./src/*` (tsconfig.json). Added new alias `@/drizzle/*` →
  `./drizzle/*` on 2026-09-24 so DB schema is never imported via long relative paths again.
- `drizzle/schema.ts` lives at **repo root**, not under `src/`. Always import it as
  `@/drizzle/schema`, never a hand-counted `../../..` path — that's exactly how the
  original bug happened (one `../` too many).
- Next.js App Router only wires up `route.ts` as an API endpoint when it's inside
  `src/app/**`. Files under `src/lib/**` are just regular modules, never real routes,
  even if named `route.ts`. All 3 auth routes were originally misplaced under
  `src/lib/auth/**` and have been moved to `src/app/api/auth/{login,logout,me}/route.ts`.
- `src/middlware.ts` (typo) has been renamed to `src/middleware.ts`. Auth middleware is
  now LIVE — every non-public route requires a valid session cookie. Public paths:
  `/login`, `/api/auth/login`. Admin-only prefixes: `/admin`, `/api/admin`.
- No `.env` / `.env.local` in repo. Required env vars found so far: `DATABASE_URL`
  (Neon/Postgres, used in `drizzle.config.ts` and `src/lib/db/index.ts`), `JWT_SECRET`
  (used in `src/lib/auth/jwt.ts`). No `.env.example` exists yet — should be added.
- `npx tsc --noEmit` will show a `LayoutProps` name-not-found error in
  `src/app/layout.tsx` on a totally fresh clone before `next dev`/`next build` has ever
  run — that's expected (Next 16 generates that global type into `.next/types/`), not a
  real bug. Don't waste time chasing it in isolation; re-check after a real `next dev`.
- Repo had no `node_modules` on clone; `npm install` works fine (no network issues,
  all deps resolve from the public registry).
