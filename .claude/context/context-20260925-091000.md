## Key decisions

- Radix UI Dialog (not shadcn/ui) for modals — lightest addition given no
  existing component library in `package.json`.
- Attendance status selection is a modal; roll-number entry itself is NOT
  (preserves rapid-entry speed for the core workflow) — this is the one
  place "modal-ize everything" was deliberately NOT applied literally, for
  a stated UX reason. Type-ahead (this session's newest ask) will replace
  the roll input with a live-suggestion search box, but the "select →
  modal" split stays: picking a suggestion still opens the same status
  modal, it's only the lookup step that becomes live/typeahead instead of
  a separate submit.
- Calendar and Login are the only two pages NOT converted to any
  modal-based pattern, by deliberate, user-unobjected-to design choice.
- Desktop nav = sidebar (replacing the old top bar entirely, per explicit
  user request: "make it in the side instead of at the top in desktop
  view"). Mobile nav = bottom tab bar (4 primary + "More" modal sheet),
  per explicit user confirmation.
