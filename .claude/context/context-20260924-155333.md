## Root cause analysis
Two distinct bugs found, the reported one being a symptom of a bigger structural problem:

1. **Reported bug**: `src/lib/auth/login/route.ts` imported schema via
   `"../../../../../drizzle/schema"` — one `../` too many, resolving outside the repo root.
   (`src/lib/db/index.ts` had the correct 3-level relative path to the same file, which is
   how the miscount was confirmed.)

2. **Bigger issue (found while reading, not in the original report)**: the three
   `route.ts` files (`login`, `logout`, `me`) were physically located under
   `src/lib/auth/**`, NOT under `src/app/**`. Next.js App Router only registers
   `route.ts` files that live inside the `app/` directory — files under `src/lib` are
   never wired up as HTTP endpoints, regardless of their content. Confirmed this was
   unintentional (not just unused code) because:
   - `src/middlware.ts` middleware explicitly whitelists `"/api/auth/login"` as a public path.
   - `middleware.ts`'s matcher treats any non-public path (including `/api/*`) as requiring a session.
   - There was no `src/app/api` directory at all before this session.
   So the login/logout/me endpoints the app depends on did not exist as routes at all —
   the app was non-functional for auth, independent of the TS error.
